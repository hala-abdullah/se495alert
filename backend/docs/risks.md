# Risk Register — PSU Alerts & Notifications

*Phase 1 deliverable, reviewed at the weekly team review; items marked ★ are
reviewed every milestone. Revision 2026-11-02 adds R12–R16 from the supplied
`Requirments Doc.md` / `Design Doc.md` reconciliation
([reconciliation note](reconciliation-2026-11-02.md)) and compacts NFR
references to the current NFR-1…NFR-24 numbering.*

| ID | Risk | Likelihood | Impact | Mitigation | Owner |
|----|------|-----------|--------|------------|-------|
| R1 ★ | Authorization model misread (officers too powerful / too restricted) — Q1 and Q14 still open | Medium | High | Build authorization as data (scope and course grants, not hard-coded roles); all sends go through one choke-point service; the three sender paths (officer scope, faculty course, comms_admin) are tested separately (AC-3.x, AC-14.1, NFR-1) | Dev |
| R2 ★ | Scope creep: approval workflows, dedupe, real gateways, templates, or a web dashboard sneak into v1 (device prefs, categories, read status, filtering, bilingual, course alerts, comments **are** committed scope as of 2026-11-02) | High | High | Out-of-scope list and conflict table in [requirements.md](requirements.md); any new ask goes through impact analysis (Phase 5 process); weekly review checks scope | Dev |
| R3 | Simulated delivery diverges so far from real channels that PSU cannot evaluate realism | Medium | Medium | Single `ChannelAdapter` interface; email adapter uses the real Django email stack (console backend), so only SMS/push are pure simulations; the push payload carries the real `sound`/`vibration_pattern`/`bypass_mute` fields so urgency presentation is demonstrable (ADR-002) | Dev |
| R4 ★ | AI-generated code skips or weakens server-side checks (a course "system controls" violation) | Medium | High | Every change reviewed against the AC list before commit; authorization tests written **independently** of the implementation; misuse cases mandatory in Phase 4; Flutter client never trusted as an authorization layer (AC-3.6) | Dev |
| R5 | Stakeholder answers (Q1–Q5, Q13–Q17) arrive late and force rework of severity/ack/authz/course/comment policy | Medium | Medium | Requirements written as OPEN-Q with cheap-to-change seams (config-driven severity, flag-driven ack, data-driven grants); recommendations documented so answers can be fast | Dev |
| R6 ★ | Real-looking contact data leaks into seed data, logs, or demo screenshots | Low | High | Synthetic-only rule (NFR-3, A-13); `example.edu` domain rule; log lines use user IDs; pre-demo checklist; secret/synthetic-data scan task (T3.19) | Dev |
| R7 | Timeline slip: one developer, Milestone 2 includes change request + demo + reflection, and scope grew by a Flutter client, courses, exams and comments | High | High | Task plan front-loads the main workflow (auth → compose → send → deliver) in Weeks 3–5; Flutter scaffold early (T3.1); comments/categories/reporting later; stretch items explicitly deferred | Dev |
| R8 | Environment friction (missing tooling — e.g., Git was absent on the dev machine) | Low | Low | Resolved 2026-10-19 (Git via winget); Django toolchain documented in README; Flutter install is now a tracked prerequisite (see R12) | Dev |
| R9 | SQLite/dev habits (e.g., reliance on DEBUG) leak into demo | Low | Low | Settings review before demo; README states the deployment boundary; NFR-13/NFR-22 startup guard refuses non-local configurations without HTTPS/encryption acknowledgement | Dev |
| R10 | "Acknowledged" mistaken for "read" in demos — overclaiming what the prototype proves | Medium | Medium | Demo-script language fixed: ack is an explicit user action, not a read receipt; README limitations state this (structurally backed by A-17, AC-13.2); the app shows both states separately | Dev |
| R11 ★ | Bilingual EN/AR scope (NFR-19/NFR-20) underestimated: untranslated strings or half-mirrored RTL surfaces late | Medium | Medium | Translation pass is its own task (T3.20), not folded into other UI tasks; ARB key-parity test + `Directionality.rtl` widget tests + AR emulator pass gate the demo; sender-authored content (A-20) removes translation QA from alert bodies | Dev |
| R12 ★ | **Flutter client adds a second toolchain, a client/server contract to keep in sync, and emulator/setup cost** for a one-developer team | Medium | High | Flutter scaffold is task T3.1 (front-loaded, so the toolchain risk surfaces in Week 3, not Week 7); the API contract in [data-model-and-api.md](design/data-model-and-api.md) is the single source of truth; widget tests run without a device; the client holds no authorization logic (AC-3.6) | Dev |
| R13 | **Course/section/enrollment data is synthetic** and may not match PSU's structure; faculty grants could be modelled wrongly | Medium | Medium | Course/Section/Enrollment/FacultyAssignment are ordinary tables replaceable by a SIS import at handoff (A-22, Q17); targeting always resolves through enrollments *active at send time* and snapshots the result (AC-14.3); no real student records are ever imported | Dev |
| R14 | **Comments create an abuse and moderation surface** (harassment, spam, personal data posted by recipients) | Medium | Medium | Recipient-only posting, plain-text 1–500 chars, escaped output, soft-delete with audit trail, moderation queue for `comms_admin` (US-17, AC-17.2/17.4); rate limiting is a known gap documented for PSU review; policy question Q13 | Dev |
| R15 | **Encryption/concurrency claims over-read** — evaluators assume the demo stores data encrypted or serves production traffic | Medium | High | NFR-22 and NFR-24 state the boundary explicitly; the security note says the demo DB is **not** claimed encrypted; the startup guard requires HTTPS/encrypted-storage acknowledgement outside localhost; PostgreSQL and SQLCipher are named handoff items | Dev |
| R16 | **"Push within 1 minute" mismatched between supplied docs and the no-gateway constraint** — the demo could look like it fails a stated requirement | Medium | Medium | NFR-23 restates the requirement as a measurable simulated-delivery SLA (terminal rows visible ≤60 s) with a timed test; race-free synchronous dispatch; Q16 records that real gateway timing is a handoff metric | Dev |

*Risk review cadence: weekly (brief's suggested ritual), plus before each
milestone submission. R12–R16 were added after the 2026-11-02 reconciliation;
each is tied to a mitigation that is already a task or an explicit boundary.*
